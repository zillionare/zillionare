> 本文是基于公开研究思路写成的原创中文实验文章，不是原文逐段翻译，也不构成投资建议。配套代码位于本文同一目录的 `strategy.py`。

许多“大模型交易策略”一开始就问错了问题：明天会涨还是会跌？对流动性很好的资产而言，要求一个语言模型给出稳定的隔日方向预测，往往是把它推向最不擅长、也最难验证的位置。

这里换一个问题：**在不同的市场状态里，我今天应该暴露多少风险？** 这不是让模型找出神秘 alpha，而是让它在一套已经明确的风险框架中，对仓位作有限选择。大模型只能在“满仓、半仓、低仓”三档中回答；它不能做空，不能加杠杆，也不能直接发出订单。

这种限制很重要。它把模型从“交易员”降级为一个有记录、可替换、可审计的风控顾问。

## 这份实验如何工作

程序先用收盘价构造三类特征：20 日趋势、20 日实现波动率，以及价格相对 20 日均线的 Z-score。它们被翻译成自然语言状态，例如：

`趋势上行｜波动偏高｜价格偏强`

每天的状态不是拿来解释当天收益，而是用于决定**下一交易日**的仓位。回测在每月第一个交易日重新统计过去三年的历史：每一种状态出现过多少次，随后的日收益均值是多少，风险调整后的得分如何。代码故意丢弃了紧邻决策日、尚未实现的那一笔收益，避免把今天的答案偷偷放回昨天的训练集。

默认的 `rule` 模式用明确规则分仓：样本不足时半仓；历史均值和风险调整表现都较好时满仓；两者都较弱时低仓。它是整个实验的对照组。只有当读者设置 `DEEPSEEK_API_KEY` 并选择 `deepseek` 模式时，程序才会把同一张状态统计表交给 DeepSeek，要求它返回三档仓位的 JSON。任何网络错误、密钥缺失或格式错误都会在缓存文件中留下原因，然后退回规则基准，而不会悄悄改写回测结果。

## 为什么不直接接 Yahoo Finance

为了让大陆读者能够运行，这个版本优先读取本地 CSV；数据从何处获得、是否复权、是否有授权，都由研究者自己掌握。若已拥有 Tushare Token，可以用 `--tushare-index 000300.SH` 下载中证 300 指数日线。指数方便说明方法，但不等于可直接买入的资产；要研究 ETF 或个股，应导出相应品种的复权 CSV，并重新设定成本与交易约束。

```bash
pip install -r requirements.txt
python strategy.py --csv data/000300.SH.csv --out output/rule
```

使用 DeepSeek 的命令如下：

```bash
export DEEPSEEK_API_KEY='你的 API Key'
python strategy.py --csv data/000300.SH.csv --policy deepseek --out output/deepseek
```

每次运行会生成 `daily_results.csv`、`metrics.json` 和 `policy_cache/`。最后一个目录尤其值得保留：它包含每个月模型或规则看到的统计数据、作出的仓位映射以及来源。没有这份记录，“LLM 改善了风控”的说法便无法复核。

## 真正棘手的 bug：风控把自己锁死

回撤止损经常有一个不显眼的逻辑陷阱。假设策略亏损超过阈值，于是把仓位降为零；仓位为零后净值不再变化，因而回撤永远不能自然收复；次日系统再看到同一回撤，又继续把仓位设为零。一个本意为短暂保护的止损，变成了无限期停摆。

`strategy.py` 为此设置了两层机制：短暂的冷静期，以及 `max_flat_days` 后的强制再入场。它并不声称强制再入场必然正确；它只是把“永远不再参与市场”从一个隐蔽的程序事故，变成一个必须明确讨论的研究选择。

## 怎样读结果

请不要只看年化收益。至少同时比较：

- 年化波动率：仓位调节是否真的降低了组合风险；
- 最大回撤：保护发生在何时，又付出了什么机会成本；
- 平均日换手：低频信号是否因为频繁调仓被交易成本吞掉；
- 规则与 LLM 的并排结果：若规则更好，应删除 LLM，而不是替它寻找解释。

程序以 5 个基点的单边成本为默认假设，仅用来提醒读者成本存在。对 A 股、ETF 或跨境产品，这个数字都不是现成答案。涨跌停、停牌、最小交易单位、申赎、税费和冲击成本也未被纳入；因此它是日频研究回测，而不是可直接投入资金的交易系统。

## 结语

大模型在这里最有价值的身份不是预言者，而是受约束的比较器：它读一张已经由历史数据生成的状态表，并对不确定性作有限度的仓位判断。它若不能稳定优于朴素规则，就没有理由留在系统里。

这比“用 AI 预测市场”更克制，却也更接近一套值得继续研究的量化工作流。
