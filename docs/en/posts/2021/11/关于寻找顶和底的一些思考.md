The `scipy` library offers signal processing functions like `argrelextrema` to detect market tops and bottoms. Judging by its name, this function identifies the coordinates of relative extrema. Let’s examine how it works:

```python
def bs_signals(bars):
    from scipy.signal import argrelextrema
    ma = moving_average(bars["close"], 5)
    
    peak_indexes = argrelextrema(ma, np.greater)
    peaks = peak_indexes[0]

    # Find valleys(min).
    valley_indexes = argrelextrema(ma, np.less)
    valleys = valley_indexes[0]

    assert abs(len(peaks) - len(valleys)) <= 1
    
    bars = bars[4:]
    # Plot main graph.
    (fig, ax) = plt.subplots()
    ax.plot(np.arange(len(bars)), bars["close"], color='c')
    ax.plot(np.arange(len(bars)), ma, color='b')

    # Plot peaks.
    peak_x = peaks
    peak_y = bars['close'][peak_x]
    ax.plot(peak_x, peak_y, 'gv', label="Peaks")

    # Plot valleys.
    valley_x = valleys
    valley_y = bars['close'][valley_x]
    ax.plot(valley_x, valley_y, 'r^', label="Valleys")
     
    trades = []
    gains = 1
    order = None

    vertex = sorted([*peaks, *valleys])
    for x in vertex:
        buy = x in valleys
        sell = x in peaks
        if buy and order is None:
            order = {
                "buy": bars["close"][x],
                "buy_at": bars["frame"][x]
            }

        elif sell and order:
            buy = order["buy"]
            sell = bars["close"][x]
            gain = sell / buy
            order.update({
                "sell": sell,
                "sell_at": bars["frame"][x],
                "gain": gain
            })

            gains *= gain
            trades.append(order)
            order = None

    return gains - 1, trades
```

The above code uses `argrelextrema` to locate peaks and valleys in a moving average. We use a moving average because it smooths out noise. Here, `moving_average` is defined as:

```python
import numpy as np
def moving_average(ts, win):
    return np.convolve(ts, np.ones(win) / win, mode="valid")
```

It employs convolution to calculate the Simple Moving Average (SMA). While NumPy’s convolution is fast, for higher performance, consider using `move_mean` from [bottleneck](https://github.com/pydata/bottleneck), which can be over 6,000 times faster (according to official documentation, though this benchmark may not directly compare with `np.convolve`).

By passing different comparison functions (e.g., `np.less` and `np.greater`) to `argrelextrema`, we can separately identify local maxima (peaks) and minima (valleys).

Next, we plot the moving average, closing prices, and detected extrema on the same chart. Finally, assuming we buy at the lows and sell at the highs, we can calculate the strategy’s returns.

The following chart shows the signal detection results for Dongfang Electric over a 60-trading-day window, ending on November 2, 2021:
![](https://gcore.jsdelivr.net/gh/zillionare/images@main/images/202110/20211030231630.png)

As shown, even with default parameters, `argrelextrema` effectively identifies tops and bottoms. The final return is 35%, while the stock’s actual price remained flat during the same period.

Impressive, but too good to be true.

So, where is the error?

The issue lies in how `argrelextrema` operates. It can only detect a peak *after* the price has already started to decline. This constitutes a look-ahead bias (a future function). It implies that the signal for today can only be identified tomorrow. However, we cannot travel back in time to execute trades yesterday.

To further validate this, let’s compare two charts around September 3, 2021:
![](https://gcore.jsdelivr.net/gh/zillionare/images@main/images/202110/20211102215632.png)
The first chart is as of September 3. Looking at subsequent data, `argrelextrema` should have flagged a bottom on this day, but it did not.
![](https://gcore.jsdelivr.net/gh/zillionare/images@main/images/202110/20211102215539.png)
The second chart is dated September 6. This time, it flags a bottom, but marks it on the previous day.

Since the moving average is calculated using closing prices, we can only identify September 3 as a low point after the market closes on September 6. If we were to buy at the September 6 closing price (in live trading, this would be even later, likely using the next day’s opening price), what would happen?

By shifting both buy and sell signals by one day in the previous method, the return drops to -13%. If we buy at the opening price at the start and sell at the closing price at the end, the return is 8.4%. After applying sophisticated mathematical methods, we successfully lost 21%. This result holds for 5-day, 10-day, or 3-day moving averages.

Ideally, it’s beautiful; realistically, it’s harsh.

However...

Experienced investors often notice that around position 5, the stock price stalls for several days, and the moving average flattens. There is a common stock market proverb: "If it doesn’t hit a new high in three days, sell" (particularly applicable to strong momentum stocks). This is because if the price doesn’t make new highs, the moving average flattens as seen near position 5 in the chart above. Subsequently, the price may either break out of the platform to start a second wave or decline. Therefore, our strategy could be: use the algorithm to detect when the moving average flattens and issue a warning (at which point we might partially reduce positions), then wait for a clear signal before deciding to fully exit (or enter).

Assume we can detect the flattening signal one day before `argrelextrema` identifies the peak. If we are at a high point, we sell half the position. Once `argrelextrema` confirms the signal, we sell the remaining position. This modifies the entry and exit logic as follows:

```python
if buy and order is None:
    order = {
        "buy": close[x] * 0.5 + close[x+1] * 0.5,
        "buy_at": bars["frame"][x+1]
    }

elif sell and order:
    buy = order["buy"]
    sell = close[x+1] * 0.5 + close[x] * 0.5,
    gain = sell / buy
    order.update({
        "sell": sell,
        "sell_at": bars["frame"][x+1],
        "gain": gain
    })
```

With this adjustment, the return is 5%. While lower than a buy-and-hold strategy, this is income earned through skill rather than luck, making it repeatable.

The problem now becomes: how do we detect when a moving average is flattening? This is not trivial. However, let’s first clarify the actual utility of the peak and valley detection method discussed above.

As analyzed, peak and valley detection is ex-post; the algorithm can only detect them after they have formed. While this may not offer direct guidance for trading, it can be used to label data for machine learning applications.

The following chart shows the results of labeling peaks and valleys in the Shanghai Composite Index over a specific period using the aforementioned method:
![](https://gcore.jsdelivr.net/gh/zillionare/images@main/images/202111/20211111170152.png)

We first smooth volatility using a moving average, then detect peaks and valleys using `argrelextrema`. We then make minor adjustments to align these points with the actual stock price rather than the moving average. Using 30-minute data for the Shanghai Composite Index over the past six years, we identified 734 peaks and 738 valleys, creating a labeled dataset.

With this labeled data, we can train and validate our machine learning models. Surprisingly, the dataset size is not large. This also indicates that in the China A-shares market, once a trend forms, it tends to persist for some time. This serves as a footnote explaining why quantitative models have room to operate effectively.
